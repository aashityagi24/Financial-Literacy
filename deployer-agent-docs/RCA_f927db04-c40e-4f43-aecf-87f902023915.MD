# RCA — CoinQuest (smart-money-learn-5) PageSpeed redeploy did not complete

## Summary
The redeploy is blocked by **three independent problems**, two of which must be
fixed before a redeploy can even succeed, and a third that means the intended
PageSpeed changes are not actually in the code being deployed.

## Problem 1 — Hard blocker: insufficient credits (deploy never started)
The `trigger_indie` step returned:
```
insufficient_credits — Required: 50, Available: 43.96168332140032 (retryable: false)
```
A new deploy run could not be committed/charged. Nothing downstream ran.
- This is an account/billing gate. I have no tool to add credits.
- `resume_pipeline` will hit the same wall until the balance is >= 50.
- Note: the deployment shows status=`failed` and every run so far is type
  `initial` and failed — there is no successful/active run yet, despite the
  "first deploy already paid" assumption.

**Fix (User):** Top up credits to >= 50 in the Deployment billing/Resources panel,
then redeploy. (This alone is NOT enough — see Problems 2 and 3.)

## Problem 2 — Build fails: react-snap crashes during `yarn build`
Latest build run `f927db04` failed at `build_image` (frontend-build stage). Build log:
```
$ react-snap
Error: spawn ENOEXEC
    at ChildProcess.spawn (node:internal/child_process:458:11)
error Command failed with exit code 1.
```
`frontend/package.json` has `"postbuild": "react-snap"` (bare, unguarded). After
`craco build`, yarn auto-runs the `postbuild` → `react-snap` launches puppeteer's
Chromium and dies with `spawn ENOEXEC` (exec-format error — the Chromium binary
installed in the build stage is not launchable on this arm64 build). The non-zero
exit propagates and fails the whole image build.

History of this symptom across runs:
- `a299d5f7` (amd64): `yarn build` failed.
- `c3dda0f4` (arm64): a manifest override tried to `apt-get install chromium` → `apt-get: not found`.
- `f927db04` (arm64): manifest now installs chromium via `apk` successfully, but
  react-snap STILL crashes (`spawn ENOEXEC`). The Chromium-install workaround in
  `Dockerfile.cloudbuild` does not fix react-snap on this architecture.

The user described changing `postbuild` to `"react-snap || true"` so the build
no longer fails — **that change is NOT present in the pulled source** (see Problem 3).

**Fix (Code / E1):** In `frontend/package.json`, either make the step non-fatal
(`"postbuild": "react-snap || true"`) or remove react-snap from `postbuild`
entirely. Note: react-snap prerendering is not actually producing output in this
build environment, so the SEO/LCP benefit of prerender is not being realized
regardless — removing it is the cleaner option. This is a source fix (not a
manifest band-aid); the existing manifest Chromium-install override can be dropped.

## Problem 3 — The intended PageSpeed changes are NOT in the deployed source
I extracted the exact source pulled for run `f927db04` into a sandbox. None of the
described optimizations are present:
- `frontend/public/fonts/` is **EMPTY** — the 2 self-hosted WOFF2 files (Fredoka,
  Outfit) are missing. (Claimed change #1 absent.)
- `frontend/public/index.html` still contains the **render-blocking Google Fonts
  stylesheet**: `<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Fredoka...&family=Outfit...">`
  with no inline `@font-face` and no WOFF2 `<link rel="preload">`. (Claimed changes
  #2 and #3 absent.) The committed `frontend/build/index.html` also still has the
  Google Fonts stylesheet link — i.e. the prebuilt output is the pre-optimization version.
- `package.json` `postbuild` is bare `"react-snap"` (claimed #4 absent) and
  `browserslist` is still the old CRA default `[">0.2%","not dead","not op_mini all"]`,
  not `defaults, not dead, Android >= 7, Samsung >= 14` (claimed #5 absent).

**Implication:** Even if credits are added and the react-snap build failure is
worked around, the deployed app would ship WITHOUT the PageSpeed improvements,
because those edits never made it into the source that `pull_source` captured.

**Fix (Code / E1):** Verify the PageSpeed changes are actually saved on disk under
`/app/frontend` in the preview environment (fonts added under `public/fonts/`,
`public/index.html` updated to self-hosted @font-face + preload with the Google
Fonts `<link rel="stylesheet">` removed, `package.json` postbuild + browserslist
updated) and re-run the frontend build so `frontend/build` reflects them, before
redeploying.
