# RCA — CoinQuest (smart-money-learn-5) deploy not completing

## Summary
The deploy did NOT go live. There are **two independent blockers**:

1. **Hard stop (current committed run): insufficient credits.** `trigger_indie` returned
   `insufficient_credits` — Required: 50, Available: 22.13. The committed run never started building.
2. **Recurring build failure (will hit again after credits are topped up): the frontend
   `postbuild: react-snap` prerender step crashes and fails `yarn build`.**

Both must be resolved before this can deploy.

---

## Blocker 1 — Insufficient credits (BILLING / USER)
- `trigger_indie` error: `{"kind":"insufficient_credits","required":50,"available":22.13,"retryable":false}`.
- **Important correction to the handoff:** this is *not* a redeploy and the "50 ECU already paid
  on first deploy" assumption is incorrect. `describe_deployment_state` shows **all three prior
  runs are `type: "initial"` and all FAILED** (none promoted / went live). Billing records at the
  `promote` step, which never ran — so no initial deploy was ever charged, and the platform still
  bills this as the **initial 50 ECU** deploy.
- Available balance (22.13) < required (50). **Non-retryable.** The deployer agent cannot add credits.
- **Fix (User):** top the account up to ≥ 50 ECU, then redeploy.

## Blocker 2 — react-snap prerender fails the production build (SOURCE / E1)
Evidence (build logs, runs c3dda0f4 and f927db04):
- `frontend/package.json` scripts: `"build": "craco build"`, **`"postbuild": "react-snap"`** (bare,
  fatal — there is NO `|| true` guard, contrary to the handoff note). react-snap `^1.23.0` is a
  dependency and a `reactSnap` config block is present (`puppeteerArgs: --no-sandbox`).
- `yarn build` runs `craco build` then automatically runs `postbuild` (react-snap). react-snap needs
  a Chromium/puppeteer browser to prerender the 7 pages. In the **arm64 Alpine** Cloud Build container
  it crashes:
  - Run c3dda0f4: a Dockerfile step tried `apt-get install chromium` → `/bin/sh: apt-get: not found`
    (base image is Alpine/apk) → exit 127.
  - A manifest override (current `Dockerfile.cloudbuild`) was then written to install Chromium via
    `apk` and set `PUPPETEER_SKIP_CHROMIUM_DOWNLOAD=true` + `PUPPETEER_EXECUTABLE_PATH=/usr/local/bin/headless-chromium`.
  - Run f927db04 (with that override): Chromium install succeeded, but react-snap **still** crashed:
    `$ react-snap` → `Error: spawn ENOEXEC at ChildProcess.spawn` → `error Command failed with exit
    code 1` → `yarn build` failed → image never produced.
- `spawn ENOEXEC` = react-snap/puppeteer could not exec the browser binary it was handed (puppeteer
  1.x bundled by react-snap 1.23 targets an amd64 Chromium snapshot; on arm64 Alpine the launch path
  is broken). The manifest-side Chromium approach has already been attempted once and did not fix it.

### Why this is a code (E1) fix, not a manifest fix
- react-snap prerendering is the **app's own build step**. The robust fix is in the repo, not the
  deployment manifest. Recommended options for E1:
  1. **Make the prerender non-fatal** so a browser-launch failure never breaks the deploy:
     change `"postbuild": "react-snap"` → `"postbuild": "react-snap || true"` (matches what the
     handoff *claimed* was already done — it is not in the committed source).
  2. **Or gate react-snap behind an env flag** and skip it in the production build
     (e.g. `"postbuild": "if [ \"$DISABLE_PRERENDER\" != \"1\" ]; then react-snap; fi"`), since this is
     a Cloudflare-frontend app where SSG prerender is optional.
  3. **Or upgrade/replace react-snap** with a prerender tool that supports a modern system Chromium
     on arm64 Alpine, if prerendered HTML is actually required for the LCP optimization.
- Note: option (1)/(2) means the LCP-optimization goal ("rendering matches prerendered HTML") won't
  be achieved unless prerender actually runs — flag that trade-off to the user if they rely on the
  prerendered `<h2>` fix for LCP. If prerendered output is required, pursue option (3).

## Recommended order
