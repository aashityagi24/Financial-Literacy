# RCA — CoinQuest (smart-money-learn-5): `/static/*` missing gzip + Cache-Control on coinquest.co.in

## Problem statement
User reports `https://coinquest.co.in/static/js/main.*.js` returns ~604 KB with **no `Content-Encoding`** and **no `Cache-Control`**, despite `server.py` having GZipMiddleware (line 1395) and emitting `Cache-Control: public, max-age=31536000, immutable` for `/static/*` (lines 1814-1822).

## TL;DR root cause
**`coinquest.co.in` is NOT served by this Emergent deployment.** It is pointed at a **separate, user-managed server** (DigitalOcean droplet `143.110.254.164`, `Server: nginx/1.24.0 (Ubuntu)`) running a **stale/self-hosted copy** of the frontend. The missing/absent headers are produced entirely by *that* box, not by anything in the Emergent pipeline. The actual Emergent production URL serves the correct headers already.

## Evidence

### 1. This deployment is a `cloudflare` frontend
`describe_deployment_state`: `frontend_type = cloudflare`, template `fastapi_react_mongo_shadcn_base_image`, live URL `https://smart-money-learn-5.emergent.host`.
`build-frontend-artifacts.sh` uploads the built frontend to Cloudflare R2 via `s5cmd sync`. A Cloudflare worker serves `/static/*` from R2 and proxies only `/api` to the k8s backend.
=> **FastAPI never serves `/static/*` in production.** The GZipMiddleware + `Cache-Control` code in `server.py` only runs for requests that reach FastAPI (i.e. `/api/*`); it has no bearing on static asset headers in either serving path.

### 2. The real Emergent production URL ALREADY serves correct headers
`GET https://smart-money-learn-5.emergent.host/static/js/main.63b5fd8f.js`:
- `200`, `Server: cloudflare`, `CF-Ray: a5b4469818d6da2f-ORD`
- **`Content-Encoding: gzip`** (184,027 bytes on the wire; ~604 KB uncompressed)
- **`Cache-Control: public, max-age=31536000, immutable`** ✅
Both headers the user wants are present and correct here.

### 3. coinquest.co.in is a different, user-owned server
`GET https://coinquest.co.in/static/js/main.63b5fd8f.js`:
- `200` but **`Content-Type: text/html`**, only **3,309 bytes**, `ETag: W/"6afa98a0-1fd6"`, **no `Cache-Control`**
- `Server: nginx/1.24.0 (Ubuntu)`, **no `CF-Ray`** (not behind our Cloudflare)
This is NOT the JS bundle — it is an HTML SPA-fallback page. The hashed bundle `main.63b5fd8f.js` **does not exist** on that server, so its nginx falls back to `index.html`. That server also runs a **different/older build** than our R2 copy (different ETag).

### 4. DNS proves separate infrastructure
- `coinquest.co.in` / `www.coinquest.co.in` → `143.110.254.164` (single DigitalOcean IP, user-managed VPS)
- `smart-money-learn-5.emergent.host` → `104.18.14.241`, `104.18.15.241` (Cloudflare anycast)

### 5. Domain is not attached to this deployment
`list_domains` → empty. `check_domain_status` → no domains. coinquest.co.in was never linked in the Emergent Domains tab, confirming the custom domain is handled entirely outside Emergent.

## Answers to the four specific questions
1. **FastAPI or nginx for `/static/`?** Neither, on the real prod URL — it's the Cloudflare worker reading from R2 (which supplies gzip + immutable cache). FastAPI's gzip/cache code is bypassed because the frontend is `cloudflare` type. On `coinquest.co.in` it's the **user's own nginx (Ubuntu 1.24.0)** — unrelated to the Emergent deployment.
2. **Production nginx config:** The in-pod nginx (used only for `kubernetes` frontends) has **no `/static/` block** — only `location / { try_files $uri /index.html; }` (SPA fallback) and `location /api { proxy_pass 127.0.0.1:8001 }`. For this cloudflare deployment that pod nginx isn't even in the public static path. The nginx producing the user's observed headers is on `143.110.254.164` and is not readable by Emergent tooling.
3. **A proxy stripping headers?** Not on Emergent infra — headers arrive intact on emergent.host. The "stripping" is simply the user's own nginx on coinquest.co.in not setting Cache-Control / not gzipping the JS and serving an HTML fallback for the current bundle hash.
4. **Current `Cache-Control` on coinquest.co.in/static/js/...:** **absent**, and the response is `text/html` (3,309 B SPA fallback), not the JS. On the real prod URL the same path returns `Cache-Control: public, max-age=31536000, immutable` + `Content-Encoding: gzip`.

## Fix
This is **not** an Emergent pipeline, manifest, secret, or `server.py` issue — the Emergent production URL is already correct. The user must decide how coinquest.co.in should be served:
- **Preferred:** repoint `coinquest.co.in` DNS at the Emergent deployment and add it under Deployment Panel → Domains, so it is served by the Cloudflare worker/R2 (which already emits gzip + immutable cache). This also eliminates the stale self-hosted build.
- **Or**, if they intentionally self-host on `143.110.254.164`, fix that server's own nginx: deploy the current build so `main.63b5fd8f.js` exists, enable `gzip`/`gzip_static` for JS/CSS, and add `Cache-Control: public, max-age=31536000, immutable` for `/static/`. Emergent has no access to that box.

No source change is warranted (the FastAPI static headers are irrelevant to a cloudflare frontend and the real prod URL is healthy).
