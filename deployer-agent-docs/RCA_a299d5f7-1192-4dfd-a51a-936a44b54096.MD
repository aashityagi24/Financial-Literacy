# RCA — CoinQuest (smart-money-learn-5) build_image failure

## Symptom
Initial deploy fails at **build_image**. The frontend compiles fine (`craco build` succeeds) but the **`postbuild` react-snap prerender** crashes, which makes `yarn build` exit 1 and fails the Docker build.

## Root cause (proven)
1. `frontend/package.json` has `"postbuild": "react-snap"` and `react-snap@^1.23.0` in devDependencies.
2. react-snap@1.23 depends on **puppeteer@^1.8.0 → resolves to puppeteer 1.20.0** (confirmed in `frontend/yarn.lock`). That ancient puppeteer must download a **pinned Chromium snapshot `linux-686378`** at `yarn install` time.
3. That 2019 snapshot is no longer downloadable, so the bundled binary is absent. Original error (run a299d5f7):
   ```
   Error: Failed to launch chrome! spawn /app/node_modules/puppeteer/.local-chromium/linux-686378/chrome-linux/chrome ENOENT
   ```
   → react-snap crashes → `yarn build` exits 1 → build_image fails.

## What I changed (manifest fixes — 2 attempts, the cap)
Staged a full manifest override set in GCS (config.yaml + Dockerfile + Dockerfile.cloudbuild + entrypoint.sh + nginx.conf + build-frontend-artifacts.sh). The only functional change: in the `frontend-build` stage of **Dockerfile.cloudbuild** (and Dockerfile), install a system Chromium and point puppeteer at it:
- `ENV PUPPETEER_SKIP_CHROMIUM_DOWNLOAD=true`
- `ENV PUPPETEER_EXECUTABLE_PATH=/usr/local/bin/headless-chromium`
- apk/apt install of `chromium` (base image is **Alpine/musl**, uses `apk`), symlinked to `/usr/local/bin/headless-chromium`.

puppeteer 1.20 **does** honor `PUPPETEER_EXECUTABLE_PATH` (verified in its `Launcher.js` source).

### Attempt 1 result
`/bin/sh: apt-get: not found` → base image is Alpine, not Debian. Fixed in attempt 2 (apk).

### Attempt 2 result (current blocker)
Chromium installs cleanly, puppeteer finds it, but launch fails:
```
$ react-snap
Error: spawn ENOEXEC
    at Launcher.launch (/workspace/frontend/node_modules/puppeteer/lib/Launcher.js:132:40)
    at async crawl (.../react-snap/src/puppeteer_utils.js:188:19)
  errno: -8, code: 'ENOEXEC', syscall: 'spawn'
```
`ENOEXEC` = the path `PUPPETEER_EXECUTABLE_PATH` resolves to is the Alpine chromium **launcher wrapper**, which `execve` can't run directly (no valid exec format / shebang handling under puppeteer's direct `child_process.spawn`). It must point at the real Chromium **ELF binary** instead of the wrapper.

Manifest-fix budget (2) is now exhausted; handing off the durable fix.

## Recommended fix (E1 / source — in `frontend/`)
Pick one; (A) is the safe unblock, (B) also restores the prerender benefit.

**A. Make prerender non-fatal so the LCP fixes ship regardless** (recommended first):
- In `frontend/package.json`, change `"postbuild": "react-snap"` → `"postbuild": "react-snap || true"`.
- The 6 LCP edits (removing animate-bounce-in / contentVisibility, srcset 390w+800w, decoding=sync, hero-child-800.webp) are baked by `craco build` and are **independent of react-snap**, so they deploy even if prerender is skipped.

**B. Actually fix the prerender (keep it working):**
- In `frontend/package.json` `reactSnap` config, add `"puppeteerExecutablePath"` pointing at the real Chromium ELF the build installs (NOT the wrapper). On Alpine that is typically `/usr/lib/chromium/chromium` (verify the exact path for the base image). The manifest already installs Chromium + sets up `/usr/local/bin/headless-chromium`, so pairing that with a correct `puppeteerExecutablePath` should let react-snap launch.
- Optionally also upgrade off puppeteer 1.20 (e.g. a modern react-snap fork / puppeteer with a maintained Chromium) to avoid the dead-snapshot problem entirely.

**C. If prerender isn't needed at all:** remove `react-snap` + the `postbuild` hook + `reactSnap` config.
